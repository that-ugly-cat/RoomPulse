RoomPulse — user guide

Live polling for talks and lectures. Your audience answers from their phones; results appear as you speak. This guide walks a presenter through building a deck, running a live session, and using every question type.

What it is

RoomPulse is a self-hosted, Mentimeter-style tool built for keynotes and teaching — with a focus on argumentative and ethical questions, not just trivia. Three ideas shape it:

  • The audience follows you. No push: their screen shows whatever slide you've made active. You get manual reveal and stage control for free.
  • Zero friction. No app, no login for the audience — a 5-digit code or a QR code, and they're in.
  • Quantitative vs. moderated. Numeric types draw a chart; free-text types pass through a presenter-side moderation queue.

Getting started

  1. Open the app and register (or sign in) on the login page. Your account owns your decks — you only ever see your own.
  2. You land in the editor (your dashboard). Create a deck with the + next to the title field on the left.
  3. Add slides, then open the presenter view to project and drive the session.
  4. Share the join code or QR with the room. That's it.

The UI is available in Italian, English and German — switch with the language selector on any page.

Building a deck

A deck is a reusable template of slides. In the editor:

  • Add a slide — pick a type, write the question, fill in the type-specific config (options, labels, min/max…), then Add.
  • Reorder — drag the ≡ handle.
  • Inspect — click a slide to expand its config; rename the deck with the pencil next to its title.
  • Presenter notes — give any slide optional notes (debrief prompts, timing, reminders): expand the slide and write them in. They show only to you on the presenter view, never to the audience.
  • Edit a slide — the ✎ on a slide reopens it, prefilled, for editing. Notes are always editable; the question, options and config only while the slide has no responses yet (purge the runs to unlock it). The type can't change — delete and re-add for that.
  • Export / import a deck as JSON to move it between accounts or back it up.

The same deck can be run many times. Each run keeps its own responses, so you can reuse a deck across classes or sessions without mixing the data.

Running a session

  1. Open the presenter view for a deck (from the editor, Presenter ↗).
  2. Click a slide on the left to activate it. The first activation starts a run automatically; use New run to start a fresh one (e.g. a new class).
  3. The audience is now answering. Watch the count and results update live.
  4. Move between slides with ← Previous / Next → at the top, or by clicking a slide on the left. The active slide's presenter notes show here, above the controls — and the Notes visible toggle, next to the preview one, hides them for when this screen is mirrored or shared. It only appears on slides that have notes.
  5. Control the slide state:
    • Show results / Hide — reveal the chart to the audience (the classic dramatic reveal).
    • Reopen voting — let people change or add answers.

Next to those controls are two counters: in the room — devices polling right now, whether or not they have answered — and voters, the distinct people who answered this slide, with their share of the room. Voters is not the response count in the line above: on a multiple-answer question one person ticks several boxes (a third chip, selections, shows what the bars add up to), and on questions that accept repeated submissions one person can leave several answers.

Q&A and Donut use open / closed instead of reveal: the feed / leaderboard is always visible, and you just open or close submissions.

Purge runs (orange, top-right) wipes every run's data for the deck — responses, votes, everything — but keeps the deck and slides. It asks for a second click to confirm. Handy to reset a deck before reusing it (and it re-unlocks structural editing).

Argument chain

Ask for an argument one move at a time. Add a slide of type Argument chain and pick its stage:

  1. Claim only — everyone states a criterion.
  2. Claim + justification — the claim is carried over from stage 1 and shown above the box; they only write the reason.
  3. Claim + justification + objection — both are carried over; they only write the objection.

Stages 2 and 3 must point at the stage right before them, in the same deck. Each participant answers once per stage by default (they can correct their answer while the stage is open).

The choice that changes the exercise is which argument you respond to:

  • Your own — you object to the claim you yourself defended. Self-refutation; one objection per argument.
  • Someone else's — you are handed another participant's claim and justification, anonymously. This is the default for the objection stage, and the only way to get several objections on the same argument. Assignment is stable and balanced: the argument that has attracted the fewest objections is handed out next, and never your own.

The presenter view shows the result as a table — one block per argument, with its objections nested underneath. If an objection is said out loud in the room rather than typed, type it into the box under that argument: it joins the same table, tagged room, and is clustered with the rest.

Someone who joins late and has no earlier answer is not blocked: the inherited fields simply become writable for them.

Pre / post

Ask the same question before and after your argument and show how the room moved. When adding a slide of type scale, choice or quadrant, link it as the POST of an earlier twin. The results view overlays the two and draws the shift: the change in mean for scales, per-option deltas for choice, and an arrow between the centroids for the quadrant.

This is the strong move for ethical topics — you measure how much the argument actually shifted positions.

Quiz mode

Turn a choice question into a quiz: mark the correct option(s). Participants find out whether they were right only after they answer, their answer locks (no changing it), and the correct answer is never leaked before the reveal. Quiz mode and participant-added options are mutually exclusive.

Random groups

The randomizer splits the room into named groups. Assignment is balanced (it fills the smallest group next) and stable per participant — refreshing keeps you in the same group. Handy for break-out activities and debates.

Connections (mapping)

Two columns of items the audience links together — tap a left item, then a right item, to draw a connection (tap the pair again to undo). When you build the slide you choose:

  • Cardinality — one-to-one (each item joins at most one on the other side) or one-to-many (free fan-out: an item can link to several).
  • Direction — left→right, right→left, or undirected (it just sets the arrows).

Results aggregate into a heat matrix (left × right, each cell shaded by how many people linked that pair), shown to both you and the audience; the presenter view also draws a bipartite graph with edge thickness by frequency. Good for eliciting how the room maps concepts, causes, criteria, and the like.

Donut energizer

Not a question but a break that also produces data: a one-button endless-runner (tap anywhere or space to jump) that runs on the audience's phones. Dodge the ruins, grab donuts (+100 each), and everyone's best scores build a live leaderboard. Each player keeps their best score; retries are free. Useful when the talk is about attention or human factors — the real distribution of scores becomes a talking point. Open / closed works like Q&A: while open people play and see the top few; when you close it the full leaderboard shows.

AI argument clustering

For Claim + justification, Open text and the Argument chain, an LLM can group free responses into descriptive themes — for claim+justification along two axes (the criterion and the kind of appeal, with a criterion × appeal matrix), and for the final stage of an argument chain along criterion and kind of objection, with a criterion × objection matrix. It's descriptive, never evaluative.

Which key it uses depends on your tier:

  • Free — bring your own Anthropic API key: editor → ⚙ → paste it (stored per user). Get one at console.anthropic.com.
  • Full — clustering runs on the shared server key; nothing to configure, and your usage is metered per user by the admin.

Then, during the session, click Cluster on that slide — re-run any time to refresh as more answers come in.

Admin & tiers

Every account has a tier: free (own API key for clustering), full (shared server key, metered), or admin. Admins get a 🛡 Admin link in the editor header, opening a dashboard to:

  • Manage users — set each user's tier and activate/deactivate accounts. A guard stops you from removing the last admin.
  • See usage & cost — a running total plus a per-user breakdown of tokens and cost spent on the shared clustering key.
  • Distribute a deck — for people who can't import a JSON: pick one of your decks, tick the target users, and it's copied straight into their accounts as their own independent, editable copy.

The first admin is set on the server via the RP_ADMIN_EMAILS environment variable; the shared clustering key is ANTHROPIC_API_KEY.

Users & passwords

Anyone can change their own password from the editor: ⚙ → Change password. You need your current one. Your own session stays logged in; any other session on that account is dropped.

Admins get more from 🛡 Admin:

  • Create a user — email, name, initial password, role. Hand them the password and let them change it themselves.
  • Reset a password — the 🔑 button on their row. Their open sessions are dropped immediately, so this also works as "lock that account out now".
  • Deactivate (the Active toggle) or delete (🗑). Deactivating keeps everything and just blocks login; deleting also destroys all of that user's decks, runs and responses, and cannot be undone. Their cost history stays in the overall total.

You cannot delete yourself, and the last remaining admin cannot be deleted, demoted or deactivated — so you cannot lock yourself out of your own instance.

Moderation

Free-text types (open text, Q&A, claim+justification) show a moderation queue next to the results on the presenter view. Answers are visible by default; hide a troll with one click, show it again if you change your mind. The audience only ever sees visible answers.

Export & import

  • Deck (JSON) — Export deck / Import deck moves the template (slides + config, pre/post links preserved) between accounts.
  • Data (Excel) — Export data downloads an .xlsx workbook for the deck: an Overview sheet listing every run, then one sheet per run with the raw responses (one row each, resolved labels, claim/justification and cluster tags in their own columns) — the full history in one file, ready for a paper or a spreadsheet.

Talking to it from a chat

RoomPulse has an MCP surface: an AI assistant that supports MCP can talk to your RoomPulse directly, with a key you issue and can revoke.

  1. Open ⚙ in the editor, give the key a name (the client that will use it), and press New key. Copy it there and then — the value is shown once and never again.
  2. Point your client at https://<your-roompulse>/mcp with the header X-API-Key: <key>. Clients that cannot set headers can use the URL https://<your-roompulse>/mcp/k/<key> instead.

What it can do: list your decks, read a deck in full, list runs, read the results of any run, look at the pulse of the live room (who is connected, who has answered, the chart so far), and compose a new deck or edit slides that have no responses yet.

What it deliberately cannot do: run the room. No starting a run, no activating a slide, no opening, closing or revealing a vote. Those are scenic decisions and they belong to you, at the presenter's screen, watching the room. A key reaches exactly the decks its owner owns — never anyone else's.

Tips & troubleshooting

  • One fixed code per deck. The join code lives on the deck, not the run — the audience always uses the same code / QR, and the backend routes it to the current run.
  • Nothing on screen? The audience only sees a question once you've activated one. Until then they see a waiting screen.
  • Quiz answer won't change. That's by design — quiz answers lock after the first submit.
  • Back up your data by exporting the Excel workbook before you delete a deck; deletion is permanent and takes runs, responses and votes with it.
  • Privacy. The audience is anonymous (a lightweight browser token, no login). Treat the join code as the only gate.
